从「人在 AutoForm 里点鼠标」到「agent 自主闭环仿真」

目标链条是:代码化 FEM 建模 → 领域方法扩展包 → 可微仿真 → 世界模型 → LLM agent 闭环。 这份文档把已经落地的部分、已经证伪的部分、和真正的卡点分清楚,再给出建议的推进顺序。

一句话结论

「代码化 FEM 建模与仿真」这一步已经做到并对标验证了——只是求解器是 OpenRadioss 而不是 NVIDIA。 NVIDIA 那条路的本构部分也验证通过了,卡在接触。而真正离你最终目标最近的一步, 既不是换求解器也不是可微,是把已经跑通的仿真接进 agent 的回路里。

现状:五层,各自到哪了

从下往上就是数据到决策的路径。左侧色条是状态,不是装饰。

Agent 运行时 已有 agent_system/src/mold_agent/harness

ReAct 循环、可插拔 LLM、HITL 人审、审计留痕、markdown 人设。判定只在确定性工具里,LLM 永不判 NG。

缺口:FLD 成形极限图没做——这是 AutoForm 报告的核心指标之一。一步法展开、拉延筋、搭边标准也还没进代码。

L2

OpenRadioss 后端:已与 AutoForm 三方对标,判定一致,96 秒一次。可直接用。

Warp 自研 (wpform):本构解析验证通过(料厚误差 0.14%),膜元稳定,但双模合模接触发散。可微性也未达成。

这就是「代码化 FEM 建模」,也是 agent 未来的写入接口——agent 改的是 spec,不是 GUI。

L0

AutoForm QuickLink zip 全解:成形态网格、每节点展开平面坐标、每单元减薄/主次应变、材料卡 .mtb(逆向出流动曲线 / E / ν / r 值)、料厚、摩擦系数。不需要 AutoForm 授权或 GUI。

三个关键判断

这几条决定了推进顺序,也是我认为最容易走错的地方。

一、「代码化 FEM 建模」已经做到了,别低估它

你要的「coding 方式建模与仿真」,本质是把建模从 GUI 操作变成可声明、可校验、可复现、可被程序改写的对象。 这件事 formpipe.spec 已经做到了,而且求解器是可替换后端——换 Warp 或别的求解器,agent 侧一行不用改。

它的价值不只是代码整洁:spec 层就是 agent 的写入接口,校验层就是 agent 的即时反馈。 agent 提出一个改动,毫秒级就能知道这个改动在物理上是否荒谬,而不必等 96 秒的求解跑完再看结果异常。

依据 重构后复现旧结果:p99 减薄 27.31% vs 27.30%,相关系数完全一致,生成的 deck 逐行 diff 只差 14 行(命名 + 更精确的 r 值)。

二、自研求解器的成本在接触,不在本构——而且它不必替代 OpenRadioss

本构两天写对并验证了(料厚误差 0.14%)。接触到现在没收敛,而且降刚度只能把发散推后,不能消除。 真实成形求解器在接触上投入的工程量远超本体:分段接触、穿透历史、曲面光顺、自适应刚度。 这才是 AutoForm / OpenRadioss 几十年积累的地方。

但关键在于:wpform 不需要在鲁棒性上打赢 OpenRadioss。 两者角色不同——OpenRadioss 当「真值求解器」负责最终判定,wpform 当「可微快速模型」负责梯度和探索。 对后者,精度要求低得多,可微和快才是硬指标。想清楚这一点,wpform 的验收标准就不一样了。

依据 最后一次诊断:出事节点单元 eqps=0(板料完全未变形)、离凸模 5 mm,是被凹模一个大三角面推飞的。罚力 1.5×10⁴ 除以节点质量 2×10⁻³ g,一步即 750 mm/ms。

三、领域扩展包是最高性价比的一块,而且和求解器无关

FLD 成形极限、一步法展开、拉延筋、压边力、搭边标准、工艺方案生成——这些是 AutoForm 真正值钱的部分, 也是你手上有资料(模具工艺搭边标准.pdf、点检表、报价单、10 个真实样例)而通用 FEM 代码没有的东西。

它们不依赖任何求解器:FLD 只需要主次应变(两个求解器都输出),搭边标准是几何规则, 工艺方案是决策逻辑。现在 knowledge/*.yaml 已经开了头,继续往里填就是在造护城河。 而且下游全都要用它:agent 要靠它判定,世界模型要靠它产标签。

依据 AutoForm 报告里的三张图是 FORMABILITY / THINNING / FLD,我们目前只能复现 THINNING 一张。

路线图

编号代表依赖顺序,不是优先级排名。① 和 ② 可以并行,③ 之后才谈得上 ④⑤⑥。

① 现在~1 周

把 formpipe 接进 agent,闭合回路

agent 现在能做「读结果 → 判定 → 出报告」,做不了「改设计 → 重算」。 formpipe 已经把「改设计 → 重算」变成了函数调用,只差包成 BaseTool 挂上去。

  • simulate_forming(spec) → 结果 JSON:替代现在必须人工在 GUI 完成的那一步
  • validate_spec(spec) → 错误/警告:给 agent 毫秒级的物理合理性反馈
  • propose_change(结果, 知识库) → 新 spec:NG 时改间隙 / 摩擦 / 坯料轮廓,再跑一轮

做完这一步,「agent 自主闭环仿真建模调试」就已经实现了——只不过内环用的是 OpenRadioss,一轮 96 秒。

依赖:无。所有前置件都已验证
② 并行持续

领域扩展包:把 AutoForm 的 domain 方法搬进代码

不依赖求解器,可以和 ① 完全并行,由工程知识驱动而非数值方法驱动。

  • FLD / FLC 成形极限——最大的判据缺口。主次应变两个求解器都已输出,缺的是材料 FLC 曲线与判定逻辑
  • 一步法展开(坯料轮廓预测)——目前坯料还是借 AutoForm 展开的,这是「完全独立」的最后一块
  • 拉延筋 / 压边力 / 搭边标准 / 工艺方案与利用率
依赖:无。产出直接被 ①④⑤ 消费
③ 之后数周

wpform:换 SDF 接触,再做 AD 化改造

两件事,顺序不能反——接触不收敛的话,可微也没有意义。

  • SDF 接触:工具是刚性不变形的,可一次性烘焙成 NanoVDB 体素场(Warp 原生 wp.Volume)。查询 O(1)、法向连续、不存在棱边假阳性——现在已定位的三个接触 bug 里有两个会自动消失。这是最可能一次解决问题的改动。
  • AD 化:去掉 eqps / fp_inv 的原地改写(改双 buffer)、Newton 定步数不 break、sqrt 加安全下限。当前梯度为 NaN 或全零就是被这几处切断的。
依赖:无技术前置,但价值排在 ①② 之后
④③ 完成后

可微仿真的两个真实用途

可微不是目的,它解锁的是这两件工程上真正难做的事:

  • 参数辨识——用实测零件(减薄分布 / 回弹量)反推摩擦系数、流动曲线、压边力。这正是你列出的 parameter identification,而且是梯度方法碾压试错法的典型场景
  • 反向设计——对坯料轮廓、拉延筋布置、型面做梯度优化,而不是人工试错。这是 AutoForm 做不到的事,也是这条路线唯一不可替代的理由
依赖:③ 的 AD 化
⑤① 之后可启动

世界模型:给 agent 一个秒级的内环

96 秒一轮的求解做不了大范围探索。世界模型的角色是快速前向模型: agent 用它探索,用真求解器验证。这与 P15 的 MoSim 架构同构(仿真产轨迹 → 数据集 → 学代理)。

数据格式已经就位:sweep.py 产出的 dataset.npz 就是 工艺参数 + 逐单元几何特征 + 逐单元减薄标签 + 网格连接关系——正好是 GNN 世界模型的输入形状。 目前只跑了 6 个样本(够验证管线,不够拟合),扩到 30~50 个约 1 小时机时。

依赖:① 的自动化产数据能力;②(FLD)提供更完整的标签
⑥ 终点—

agent + 世界模型:完整的工程闭环

到这一步,agent 具备:声明式建模接口(L1)、毫秒级合理性校验(L1)、秒级前向预测(⑤)、 分钟级真值验证(L2)、领域判据(②)、以及梯度驱动的参数辨识与反向设计(④)。 这才是「自主进行闭环仿真建模调试 + 参数辨识 + 结果评估」的完全体。

依赖:①②④⑤ 全部

如果只做一件事

把 formpipe 包成 agent 的工具,闭合回路(①)

  1. 它把整条链路从「半自动」变成「全自动」——这是 agent_system README 里明确写着的当前最大缺口,而缺的那一环现在已经补好了,只是没接上。
  2. 它是后面所有阶段的前置。世界模型需要 agent 自动产数据;参数辨识需要自动化的正向求解;领域扩展包需要一个能调用它的执行体。
  3. 它的风险最低。所有零件都已单独验证过,不含未解难题——不像 ③ 的接触,存在「几周还是几个月」的真实不确定性。

需要说清楚的不确定性

  • NVIDIA 栈里没有现成的冲压 FEM。已核查:Isaac Sim/PhysX 只有刚体;Newton 的布料是弹簧膜模型(无厚度状态量、无金属塑性),MPM 是砂土流变;warp.fem 是通用 Galerkin 框架,壳单元/塑性/接触都得自研。用 NVIDIA 就意味着自研求解器,这是路线 ③ 的全部成本来源。
  • wpform 接触能不能在数周内搞定,是真的不确定。SDF 是有依据的下一招,但不能保证一次解决。所以不该让任何其它阶段阻塞在它上面。
  • crash-form 不等于增量拉延。当前无压边圈/拉延筋,平坦区应变被低估,自由边虚假过度减薄。判据已改用内部单元和高分位数规避,但这是方法本身的边界。
  • 只验证了 1 个样例。Samples 下有 10 个真实项目,只有 7 号做过三方对标。扩到 3~5 个才能说方法稳定。
  • 回弹还没做。OpenRadioss win64 预编译缺 MUMPS,隐式不可用;显式动力松弛可行但没接进 formpipe。
