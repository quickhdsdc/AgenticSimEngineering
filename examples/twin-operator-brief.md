这是用户授权 Codex 根据已有对话整理的需求补充，不是实测数据。回答中的来源必须保留。最终再制造应用尚未确定，本次机器人案例用于探索。

## 已确认的需求

- 本仓库独立运行，使用 components/harness 的 A4S AgentLoop；各种能力通过 CLI 接入。
- 已有 KUKA iiwa 14 / Unitree G1 的 Newton 仿真与原始网格 3D 回放。它们不是部署设备测量。
- 希望 Agent 通过对话完成任务定义、模型配置、语义映射、执行和证据解释，并在部署后支持监测。
- 用户授权 Codex 作为需求代理回答 Harness 的问题。代理回答必须标记 delegated_operator，不能声称用户逐条确认过代理提出的数值。

## 本次探索任务

补充：本入口仍是资料/监测探索；已新增的 KUKA 合成辨识任务通过 `ase-dialogue --case kuka-calibration` 单独选择。它能生成实际模型并完成两参数拟合/留出验证，但不提供实测校准或一般机器人自动建模。

先形成可审查的数据接入与监测方案，复用本地可运行的仿真验证工具调用。AURSAD 作为机器人监测候选；Isaac Lab Franka 插入/装拆作为另一个仿真参考候选。这是工作假设，不锁定最终应用。

1. 查询本项目能力目录，并阅读相关本地示例和文档。
2. 在会话工作目录创建 intake.json，包含任务目标、资产身份、数据来源/版本/许可状态、信号名称、单位、坐标系、时间轴、运行编号、标签处理、待补字段及来源。
3. 创建 monitoring-plan.md：说明采集、事件检测、唤醒同一 Harness、诊断证据、3D 映射和验收方法。
4. 若需要验证工具链，运行入口提供的 queue 或 KUKA Study，再导出回放；这些结果明确标记为仿真，不证明 AURSAD 接入或现场监测成功。
5. 总结实际产物与缺口；需要上下文之外的信息时调用 ask_user。已经给出的需求不重复询问。

## 补充信息规则

- 工程目标、探索顺序、产物格式可以来自委托上下文。
- 质量、惯量、摩擦、控制增益、单位、坐标系、设备阈值必须来自有版本的模型、手册、数据或测量；缺失时写 null/unknown 和补充方法。
- 若为探索提出数值，标记 assumption，写适用范围及敏感性验证方法，不升级为实测或用户确认值。
- 内部语义草案不叫官方 AAS 模板；没有目标端点时仅生成本地映射草案。
- 此入口仅支持本地材料与固定仿真 CLI。实际设备/MES/AAS 写入、联网下载和新后端安装应单独推进。
